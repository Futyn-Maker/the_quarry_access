# Exploration and looking around

- Targets are the use locations the scene has turned on, plus the scene's places. Availability comes from the native hook `UseLocationSMG026:ClientStateChanged` (0 Disabled, 1 Available, 2 LockedToUser, 3 Activated). The pawn's `AvailableUseLocations` and `OverlappingUseLocations` hold whatever box the character overlaps, turned on or not. The state flickers while the character stands in a box, so availability keeps a grace period.
- The whole game has four use-location labels, all verbs (Talk, Interact, Inspect, Examine), and draws no words over them. A name comes from the `ExplorationDestinationSMG026` standing beside it (closest pair first, within 250 cm), from its `LocaleString`, or from the level actor's name read as words (English; accepted).
- `ExplorationDestinationSMG026` actors are touch-mode waypoints (bare points, no collision); their prompts never appear with keyboard or pad. Scenes move on through `TriggerVolumeSMG` volumes watched by `GFConditionInVolume`: the mod reads the live state's `Transitions` (reached from the flow action that turned a use location on, two outers up) and offers those volumes as "Way on", never by name. Transitions that lead back to the same state (interludes) are skipped, and a way near a named target is dropped. A volume's actor location is its brush pivot, which can lie outside the volume: test against its collision (`GetActorBounds`, `GetClosestPointOnCollision`).
- The game offers one use location at a time, `CurrentUseLocation`, the nearest of the boxes the character overlaps. Reached means offered, or inside the box with nothing offered; there is no distance rule. The route's goal is the use box (`CollisionComponent`), its middle first, then spots at 0.7 of its extents, because an actor's origin can sit inside scenery.
- Routes: `NavigationSystemV1::FindPathToLocationSynchronously`. `IsPartial()` is true whenever the goal is off the mesh, so a partial route is used like a whole one. `K2_ProjectPointToNavigation` picks the polygon nearest across in 2D, so try a vertical extent of 120 cm before the wide one, or a target upstairs snaps to the floor below. Closed gates (`NavigationBlocker`) are not carved into the mesh, so routes run through them.
- Walking: `AddMovementInput` does not move this game's characters (their locomotion runs on goals). The walk holds the game's own movement keys with `SendInput`, arrows before WASD because a screen reader stops speaking on letter keys, or, with a gamepad in use, pushes the left stick through the XInput detour so the prompts stay gamepad ones. Release the keys on every way out, and stop at once on any screen, mechanic, loss of control (`IsInLoco`) or movement by the player. Judge a stall by `GetCharacterLinearSpeed()`: the body turns before it moves.
- Bearings are relative to the camera, and the game cuts between fixed cameras, so every bearing can turn at once.
- Tarot cards are timed button prompts, not use locations. Binoculars have nothing to find unless the flow runs a static exploration.
- Looking around: `GFActionStaticExplorationSMG026.POIObjects` carry yaw and pitch tolerances, but the flow's own `GFConditionIsLookingAt(LookTarget, AngleDegrees)` is what really judges (the campfire photo: 20 degrees as a half angle; 16 degrees off counted). Guidance uses the `[Combat] AimSound` switch, and T toggles it. `MulticastPOIFound` is hooked but has never been seen firing.
- Offline checks: sub-levels `Maps/Acts/<act>/<scene>/<map>/Gameplay/{Triggers,Interactions}.umap`; use-location boxes are the `Collision` BoxComponent (default sizes in `DefaultGame.ini`); the cooked Recast navmesh sits in the persistent level's `.uexp` (each tile starts with `VAND`).
- A character handed back for the seconds it takes the game to leave for the main menu is not a scene to explore: while `features::LeavingTheGame`, the keys hint and the targets say nothing, however much the world looks like itself.
- Who has the character, from the game's code and flows. The scene's explore action (`GFActionExplore`, native, no UFunctions, no instance to read) takes the local player's character, never a named one, and marks it while it runs (a native byte of the character, set on start and cleared on exit). The character's cinematic state machine (`ECinematicState`) keeps it in Loco only while it is so marked, or while `GFActionSetLocomotionAuthorised` lets it walk, or when its `bLocomotionRequiresAuthorisation` is off; otherwise Loco falls to Standby on the next update. A cutscene goes Loco → LocoToCinematic → CinematicRunning → Unmount → CinematicToLoco (the blend back) → Loco. The getters answer one state each: `IsInLoco` Loco, `IsSleeping` Standby, `IsBound` Mount, `IsBoundAndRunning` CinematicRunning, `IsInCinematicToLoco` the blend. The game's own "use the stick to move" prompt comes only in Loco, under the explore action, with the world not paused.
- Every scene lets a character walk outside an explore state only as a companion walked by an AI (`GFActionAIPossessCharacter`, `GFActionAICommand*`; Abigail beside Nick, Emma beside Jacob, Ryan and Travis behind Laura) or together with the explore action; movie mode chains the cutscenes with neither. So for the player's pawn `IsInLoco` is the explore action's hold, and it drops the frame a cutscene or the end of the action takes the character. The mod reads it at every frame (`PollControl`), logs the cinematic state whenever it changes, plays the control cues on each change (silent while `features::LeavingTheGame`), and the roaming takes the change up on the same frame. A pause freezes the state, so the pause menu plays no cue.
- A logged session bears this out: the character went from Loco to CinematicRunning the frame after a use location was pressed (state 3), and back to Loco the frame after the scene turned its use locations on again, the game drawing its prompt some 50 ms later; every playable character had `bLocomotionRequiresAuthorisation` set; and between the quit popup and the main menu the pawn went away, the frontend holding none.
- The player walks the character while there is a pawn, no menu screen is current (`watch::CurrentScreen`), no game mechanic is shown and `IsInLoco` holds. Every change of the reason is logged (`not under the player's control: a screen is up, ...`). A screen held past its closing once kept exploration off for up to 75 s after a clue viewer, while the game had long handed the character back.
